# Competition Control

Competition Control provides an OIDC-protected admin dashboard, PostgreSQL-backed competition data, match scheduling and live operations, scoring and standings, double-elimination playoffs, configurable public displays, and competition branding.

## Dashboard

The left navigation separates Competitions, Overview, Teams, Challenges, Schedule, Live control, League table, Arena, Public displays, Settings and Activity. Playoff generation, scoring and scheduled heats are part of Schedule.

- Generate equal-appearance league schedules or add individual matches. Every match has four coloured positions; fewer than four teams requires a reason and is visibly marked.
- When generating a balanced schedule, **Start-to-start interval per arena** is the exact time between match start times in the same arena. A five-minute interval means consecutive starts are five minutes apart, regardless of match duration. The interval must be at least the configured match duration. Generated spacing is retained when schedule events or late starts cascade later matches.
- Set the competition's IANA timezone in Settings (for example, `Europe/London`). Schedule times in the admin portal, public schedule displays, and match history are rendered in that timezone; changing it affects displayed wall-clock times only, not stored match instants.
- Edit or delete pending matches after schedule creation. Deleting any non-running match requires typing its number and removes its saved scores/corrections while retaining an audit entry.
- Delay changes in Live control show the total time between the original scheduled start and current effective start, not the number of delay events. Upcoming matches can have their delay reduced, restored individually, or restored in bulk from **Future matches → Undelay all future matches**. Bulk restoration only resets unstarted league matches and active playoff heats whose original start is still in the future, skips countdowns and reports conflicts with active matches, other matches or events, and never moves an overdue match into the past. Reductions preserve the delay audit trail and are rejected if the earlier start would overlap another match or scheduled event.
- Start matches with a cancellable three-second countdown, delay starts, pause/resume timers, finish matches and enter/correct scores. Automatic/manual starts, explicit delays and timer resets only push later matches when the preceding match's expected end actually overlaps the next scheduled start; the configured gap is already represented by the next start and is not added a second time. If a match is reset before its existing scheduled/effective slot, that slot is preserved; otherwise it is moved to the next full minute. Live Control includes generated playoff heats alongside league matches: ready heats move into Active at their scheduled time, can be scored from the same score dialog, and scored heats remain in Past for corrections. Live Control labels matches with saved scores and offers score correction.
- Enable competition-wide auto-run in Live control to automatically start scheduled matches at their effective times. This is the only automatic-start setting; individual matches do not have start modes. If an automatic start is late, conflicting later matches in that arena are pushed and recorded just like manual starts.
- A team or arena already occupied by a running or paused match cannot be started in another match. Manual starts, explicit delays, late automatic starts, resumes and timer resets push conflicting later matches in the same arena by whole-minute increments; updated effective times are immediately reflected in the schedule and public outputs.
- Arena diagrams use a square layout with team codes and the competition-wide position colours configured on the Arena page. Changing the four colours updates existing matches as well as future matches. Position 0 is bottom-left, then positions 1 (top-left), 2 (top-right) and 3 (bottom-right) clockwise.
- Create Timer, Arena or Corner public displays for live, server-synchronized clocks and starts. Timer, Arena and Corner displays take over the full screen for a shared two-second **GET READY**, three-second **3-2-1**, then **GO**. Countdown phases are derived from the same server timestamp on every display, and each display keeps a low-latency server-clock offset to reduce phase drift. The preparation/countdown background and alternate flash colour are configurable, as are the GO and END backgrounds. An optional final-seconds countdown (default 10 seconds, configurable from 1 to 60) appears before END. The END screen uses viewport-bounded text sizing so it fits narrow and short displays. The Timer display scales its layout to fit the viewport without a page scrollbar. Its settings can optionally show every team's score from the most recently completed, scored league or playoff match beneath the arena. The GO cue duration is configurable from one to five seconds. An optional END overlay can be shown for one to ten seconds when the match clock reaches zero. Corner displays ignore dark-theme configuration because their appearance is controlled by the chosen corner colour or the competition theme.
- The Public displays selector includes the original SR Arena, Outside, Producer, Shepherding and Staging pages from [SRComp Screens](https://github.com/srobo/srcomp-screens), rather than a visual re-creation. The original Polymer page/component markup and styles are served with the upstream MIT notice in `public/srcomp/LICENSE`; Competition Control supplies a read-only compatibility API and event stream backed by the selected competition. The standard SR schedule feed contains league matches only, while the knockout feed is explicitly selected for knockout views; Shepherding opts into both and keeps identically numbered matches distinct by bracket. The Outside display shows the schedule, leaderboard and available knockout brackets (not the league scores page); its schedule is ordered and displayed using effective slot start times so older matches with later numbers cannot appear after future matches. Arena and Producer can be pinned to an arena; Outside supports page visibility, rotation interval, leaderboard size, knockout round limit and an optional external competition link (none is shown unless configured); Staging supports a custom corner order. Their native full-screen layouts remain intact, with optional synchronized start/end cues and countdown colour settings applied to the original clock components. Each screen estimates its clock offset from a no-cache timestamp request to the Competition Control server (using the request midpoint to reduce network-latency error), then gently corrects that offset every 15 seconds. Countdown boundaries are based on the server-recorded start timestamp, and the local display pulse is aligned to server-clock second boundaries. For best alignment, the server host must itself have a correct system clock (NTP); this synchronizes displays to the server, not the physical clocks on their devices to each other.
- Configure Shepherding or Staging from **Public displays → Configure → Shepherding & staging control panel**. Shepherding controls recent-match history (0–5, default one); both displays control how many minutes after the previous match starts staging closes (0–30, default five). Staging for the next match opens at the previous match’s actual start, or its scheduled start until it begins; these times recalculate for future matches, including countdown starts and schedule changes. A match that has actually started shows staging closed, even if its prior staging window would otherwise remain open. Team codes on Shepherding are plain text coloured to match the competition-wide position colours configured on the Arena page; the board omits position headers and the arena heading for a single-arena event.
- SR screens are available to public displays only when the competition is published, live or complete. Their adapter exposes team standings, match positions and timing, scored matches, playoff brackets, configured arena colours, live delays and competition schedule events; it never exposes the authenticated admin endpoints. The live Arena/Producer match feed selects one active-or-next match per arena, includes starts initiated before their scheduled time, and ignores old awaiting-score matches so stale results cannot replace the match currently being shown. Shepherding status receives the complete schedule and evaluates the shepherd signal window against server-adjusted time. Since Competition Control records league points rather than separate game-score totals, the SR `game` score field represents accumulated match points and `league` represents total league points. SR screen assets and legacy Polymer/Web Components polyfills are vendored under `public/srcomp/` so the original HTML imports continue to work in current browsers; the Polymer dirty-check fallback remains active for background display tabs so live data continues to render without native `Object.observe`.
- Give each public display its own dark-theme setting. Schedule displays can independently hide completed events and completed matches; display options are limited to those relevant to that display type.
- Correction reasons are shown and required only when replacing existing match scores; request failures remain visible until dismissed.
- Create challenges for the selected competition, award points once per team, and undo an award if it was entered in error. Both actions are recorded in the audit log.
- Add and edit custom timed schedule events such as lunch or talks. They appear chronologically alongside matches in the dashboard, public schedule JSON and schedule displays. Event time changes shift conflicting not-yet-started matches and later matches in the same arena by whole-minute increments; active matches and start countdowns are protected from being silently moved.
- Planned schedule reflow around events or arena conflicts updates match times without marking matches as operationally delayed. A currently running match takes priority over matches awaiting score on the live public Timer, Arena and Corner displays.
- To run a multi-day event, generate the league schedule from the first day's start time, then add break events to the Schedule before relying on the final times. For example, for a day beginning at 11:00 with a 13:30–15:30 break and a 17:00 finish, add a 120-minute event at 13:30 and an "Overnight break" event at 17:00 for 1,080 minutes (until 11:00 the next day). Matches overlapping either block, and later matches in the same arena, shift automatically. Choose the match count so the desired number of league matches fit before 17:00; any remaining matches roll into day two at/after 11:00. Add a lunch event on day two after the league matches, then generate the playoff bracket with its first heat scheduled after lunch. Upcoming, unscored playoff heats can be rescheduled individually from the Schedule table. Editing a heat's planned gap enforces the minimum interval before it; its start is moved later automatically if needed, while conflicting events are also respected. To add a 20-minute buffer before the final, edit the final heat and set its planned gap to 20 minutes (or more). If a previous match runs late, entering its result cascades later heats forward while retaining the planned gaps and shifting around events.
- Open the Competitions dashboard to create/select events or permanently delete one by typing its slug. Deletion removes its teams, matches, scores, challenges, brackets, settings and displays; an audit event is retained.
- Teams can be added to a competition at any time, including after publication and after matches have been scheduled. Newly added teams are not automatically inserted into existing matches; add or edit match assignments as needed. A team already assigned to a match cannot be deactivated, and teams with recorded history cannot be deleted.
- Competition standings total match points and challenge points. Each active team can receive a given challenge award once.
- Generate and schedule double-elimination playoffs for any selected field of 2 or more teams, up to all active teams. Four-team heats are used where possible; 2- or 3-team heats handle remainders so arbitrary field sizes (including 22) can progress without excluding entrants. In a two-team heat, the winner advances and the other team takes a loss; in three- and four-team heats, the top two advance and the remaining teams take a loss. Two losses eliminate a team. Before the first playoff countdown starts, seeds and selected entrants track the latest league standings, including new league scores, score corrections, challenge awards/undos, and added teams. The Schedule page shows the highest-numbered scored league match included in the saved standings snapshot, when it was captured, and links to an admin-only sanity-check report with the full points breakdown and the exact standings used to determine seeds. Seed ranks and their standings snapshot are saved together; the report checks that the selected seeds match the top teams in that snapshot. The first playoff countdown freezes seeding so bracket progression cannot change once play begins. Scores are ranked using the frozen league seeds to break ties. The final heat ranks the remaining four, or all remaining teams when fewer than four qualified. Playoff points do not affect league standings. Brackets created before standings snapshots were introduced retain their saved seed ranks, but their original match cutoff and points cannot be reconstructed; the report explicitly marks those historical snapshots as unverifiable.
- Set the first heat's start and the minutes between heat slots, and optionally add an extra delay before the final. Heats are scheduled in dependency order, after the existing schedule by default, and shifted around timed events. When an earlier result is entered late, later heats are moved forward as needed while preserving the planned gap, including the final buffer. Future heats are scheduled before their entrants are known, then fill automatically from prior heat placements after scores are entered. The default field includes every active team.
- Playoff heats have separate schedule records and score storage, use the same score-entry dialog and synchronized timer controls, shift around regular matches and timed events, and never add their scores to league points. In Live Control, an assigned ready heat can be started before its scheduled time with **Start now**; its three-second countdown starts the timer, moves dependent heats forward while retaining their planned gaps, and checks that its arena and teams are not already active. Pause, resume or finish it from the same controls, then enter scores when it is awaiting score. An unscored running, paused, or finished heat can be reset from Live Control; this clears its timer and schedules it for the next full minute, moving later heats as needed. Reset is blocked after scores are saved. Timer, arena, and corner displays follow the active playoff heat as well as league matches. Correcting a heat requires a reason and is blocked when a dependent heat already has scores. Replacing a bracket archives its previous progression.
- Upcoming playoff heats can be edited from Schedule to change their time, arena, or planned gap while retaining dynamic team assignment. Completed or scored heats cannot be rescheduled. Deleting league matches is available in Schedule only, not Live control.
- Create public league, schedule, arena, timer and corner displays. Schedule displays show league and playoff heats plus timed events in chronological order, with four position columns coloured to match arena corners and an optional team dropdown filter. Schedule times use the competition's configured IANA timezone, including daylight-saving changes, rather than the server's timezone. Corner displays make the selected team's three-letter code primary, with options for a full-screen corner colour, a large background position number and the team name. The live clock labels upcoming starts as “STARTS IN” and running/paused match time as “TIME LEFT”. Each display provides an HTML URL and a JSON endpoint and can be embedded with an iframe.
- Schedule displays can replace clock times with a live-updating relative time (“in …” / “… ago”) and independently hide the arena column. A Match points history display lists every completed league and playoff match and the exact points scored by each team in its arena position; playoff scores remain separate from league standings.
- Live control separates matches into Active, Future matches (soonest first) and Past matches (most recent first). State changes move a match immediately to its new section without duplicating it. The four arena positions are shown as compact colour-dot/code labels instead of a large arena diagram.
- From the Schedule page, choose **Clear matches only** to remove league matches, playoff heats/brackets, scores and correction history while retaining custom timed events, teams, challenges, settings and displays. Choose **Clear all scheduled content** to also remove custom timed events. Both actions require two UI confirmations, are blocked while any league or playoff match is running, paused, awaiting score or in its start countdown, and are audit logged.
- Choose the Paper, Field or Night theme and upload a PNG, JPEG or WebP logo up to 1 MiB.
- Save one distinct colour for each of the four arena positions in Arena settings; the server applies the palette to all match position records and all newly created/generated matches.
- Dashboard data updates automatically while the page is open. Unsubmitted form edits are preserved while updates arrive; the sidebar stays fixed while the main content scrolls.
- Schedule position cells use only the colour-coded team code; the numbered positions remain in the column headings. Arena diagrams show the large position number in each cell's corner and make the synchronized "starts in" countdown prominent.

## Deployment

Docker and Docker Compose are required. The app listens on port 8080 inside the container; Compose publishes it on all host interfaces. The app does not terminate TLS. Use a TLS reverse proxy for public access and OIDC callback traffic.

1. Create `.env` using `.env.example`.
2. Set a unique `POSTGRES_PASSWORD`, a random `COOKIE_SECRET` of at least 32 characters, `PUBLIC_BASE_URL`, and the OIDC issuer, client ID, client secret and callback URI.
3. Configure the identity provider for OIDC Authorization Code with PKCE, the `openid`, `profile` and `email` scopes, and callback `${PUBLIC_BASE_URL}/auth/callback`.
4. Start the service with `docker compose up -d --build`.
5. Check `curl http://127.0.0.1:8080/health`, then sign in through the public HTTPS URL.

Every authenticated account from the configured OIDC provider currently has full administrator access. Control account enrollment and provider access in the identity provider. Sessions use HttpOnly, SameSite=Lax cookies; use `COOKIE_SECURE=true` behind HTTPS. For local-only development, use `COOKIE_SECURE=false` and do not expose the service publicly.

## Public outputs

Create outputs in the dashboard's Public displays page. An enabled display is available at:

- HTML: `/display/{display-slug}`
- JSON: `/api/public/display/{display-slug}`

League standings also have fixed compatibility routes:

- JSON: `/public/v1/{competition-slug}/league`
- Iframe: `/embed/{competition-slug}/league`
- Schedule JSON: `/public/v1/{competition-slug}/schedule` (`matches`, `events`, and chronologically sorted `items` arrays)
- Live timer JSON: `/public/v1/{competition-slug}/timer` (current match, position/colour assignments and timer state)

Displays are read-only and are available after the competition is published. Disable or delete displays from the admin page.

## Development and validation

```sh
npm test
npm run build
npm audit --omit=dev
```

Schema setup runs when the server starts. Back up the `postgres_data` volume and verify a restore before event use. Versioned schema migrations and automated API/browser integration coverage are release-readiness work.
